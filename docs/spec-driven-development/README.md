# Spec-Driven Development

Repository production changes follow this sequence:

1. [`01-feature-spec-structure.md`](01-feature-spec-structure.md) — write WHAT/WHY and resolve risky
   decisions.
2. [`02-spec-kit-artifact-system.md`](02-spec-kit-artifact-system.md) — approve spec, plan, tasks,
   contracts, and evidence ownership.
3. [`03-coding-constraints.md`](03-coding-constraints.md) — implement only approved behavior and
   validate each coherent task group.

The active feature pointer is `.specify/feature.json`. File existence does not prove approval, and a
checked task does not replace command/result evidence in `validation.md`.
