# Architecture Decision Records

ADRs record why an architectural choice was accepted and which alternatives were rejected. They are
historical decisions, not live health evidence and not a replacement for an approved feature spec.

Read ADRs in numeric order only when reconstructing project history. For current navigation, start
with [`../architecture/README.md`](../architecture/README.md) and follow the ADR links relevant to
the service or boundary being changed.

Create a new ADR when changing a service boundary, ownership rule, data authority, communication
protocol, deployment owner, or another difficult-to-reverse architectural decision. Do not silently
rewrite an old ADR to make a newer decision appear historical.
