# Implementation Plan: Stripe Test-Mode Cloud Enablement

**Branch**: `codex/gitops-phase24-stripe-cloud` | **Date**: 2026-08-23 | **Spec**: [spec.md](spec.md)

## Summary

Connect the existing Payment Stripe Checkout implementation to the single EKS development
environment through explicit secret provisioning, an all-switches-together ConfigMap change, Argo
reconciliation, and bounded test-mode evidence. The production-like cloud webhook path is blocked
until the owner selects an HTTPS transport; the default recommendation is a domain-backed ACM
certificate and HTTPS Gateway edge.

## Technical context

**Language/Version**: Kubernetes YAML/Kustomize and PowerShell 7; no Java behavior change planned.

**Primary dependencies**: Existing Payment image, Argo CD, EKS, Phase 15/21/22 scripts, Stripe Test
mode, and either an HTTPS AWS edge or Stripe CLI interim relay.

**Storage**: Existing `payment_db`, `payment-secrets`, Kafka topics, and provider receipt/outbox
tables; no new database or PVC.

**Testing**: Kustomize client dry-run, script parse/static tests, Phase 15 validation/apply, Phase 22
guard, Argo health/rollout, Stripe test-mode bounded E2E, duplicate webhook replay, and rollback.

**Target platform**: EKS `flash-sale-dev`, namespace `flash-sale`, Argo Application
`flash-sale-cloud`, API Gateway external edge only.

**Constraints**: Test mode only; no `.env` modification by the agent; no values in output; no raw
card or webhook body; no live flag change before HTTPS decision and owner secret confirmation.

## Design

### Desired-state ownership

`infra/k8s/overlays/cloud/config/payment-service-runtime-config.yaml` remains the only desired-state
owner for runtime switches. A single reviewed patch changes the seven booleans from `false` to
`true`; provider URL/mode/topic names remain unchanged. `payment-secrets` is generated by Phase 15
from the ignored owner `.env` and is never represented in Git.

### Webhook edge

The Gateway forwards `POST /webhooks/v1/payments/stripe` without changing bytes or
`Stripe-Signature`. For decision A, add an HTTPS-only cloud edge with a domain and ACM certificate;
for decision B, keep the path private and use Stripe CLI relay only for interim testing. Direct
Payment exposure and HTTP-only Stripe registration are prohibited.

### Rollout and rollback

Argo reconciles the ConfigMap and Deployment. The operator verifies all seven switches, readiness,
Kafka consumer/outbox/recovery health, and private backend Services. Rollback is a Git revert that
sets all seven switches to `false`; it does not delete Secrets, databases, topics, PVCs, or receipts.

## Implementation sequence

1. Resolve the webhook transport and accept the HTTPS ADR.
2. Add the Phase 24 contract/runbook and bounded preflight/rollback scripts.
3. Validate and explicitly apply owner Stripe secrets using Phase 15.
4. Enable all seven flags in one cloud ConfigMap change; run Kustomize dry-run and CI.
5. Reconcile with Argo and verify readiness/health/flags.
6. Execute checkout/webhook/replay evidence and record only sanitized identifiers/statuses.
7. Revert the ConfigMap and verify safe rollback.
