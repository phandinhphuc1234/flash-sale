# Data Model: Gateway-Owned Error Handling

**Feature**: `011-gateway-error-handling`

This feature has no database, schema, migration, cache, Kafka payload, or durable state. The models
below exist only for one reactive HTTP exchange.

## GatewayErrorResponse

Immutable wire record written only for a Gateway-owned failure.

| Field | Type | Required | Rule |
|-------|------|----------|------|
| `code` | string | Yes | Exact name from the approved `GatewayErrorCode` taxonomy |
| `message` | string | Yes | Exact deterministic safe message owned by the selected code |
| `traceId` | string | Yes | Non-blank normalized caller value or one server-generated value for this exchange |

The record contains no timestamp, request body, exception message, stack trace, downstream address,
provider detail, or service-specific metadata.

## GatewayErrorCode

Immutable edge taxonomy. Each value owns one HTTP status and one safe client message.

```text
INVALID_ADMIN_REQUEST
UNAUTHENTICATED
CATALOG_ADMIN_REQUIRED
ACCESS_DENIED
DOWNSTREAM_UNAVAILABLE
AUTHENTICATION_UNAVAILABLE
GATEWAY_INTERNAL_ERROR
```

The taxonomy is not a domain model and must not include Product, Order, Payment, inventory, or other
service business errors.

## Exchange Correlation State

`GatewayTraceIdResolver` may attach one generated trace ID to the current `ServerWebExchange`.

- **Lifetime**: one HTTP exchange only;
- **Identity format**: Java UUID string generated by the server;
- **Reuse**: every Gateway-owned writer/observation call in the same exchange uses the stored value;
- **Caller compatibility**: a valid trimmed first `X-Trace-Id` value wins and is preserved;
- **Invalid input**: absent, blank, or longer than 128 characters generates an error correlation ID;
- **Admin rule**: generation does not make an invalid Product Admin request valid;
- **Durability/cleanup**: none; the exchange owns lifecycle and garbage collection.

## State Transitions

There is no business lifecycle. The technical exchange moves through at most one of these terminal
outcomes:

```text
request
├── Gateway-owned failure -> classify -> resolve trace -> observe -> write once
├── downstream HTTP response obtained -> pass through unchanged
└── response already committed -> propagate failure without rewriting
```

No state is shared across concurrent requests.
